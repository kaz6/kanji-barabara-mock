### R-001 N5 の字は KANJIDIC2 の jlpt=4（103字）で代用する

- 決めたこと：data/kanji.json は KANJIDIC2 の旧4級（103字）から作る。`tools/build_data.py --kanji-list <ファイル>` で tanos の表に差し替えられる
- 理由：KJ-001 の指示。tanos の表はまだ手元にない（D-009 の「まだ確かめていないもの」）
- 注意：D-009 では「103字版」が tanos 以外の非公式の表として却下されている。今回は差し替えるまでのつなぎで、D-009 を覆すものではない
- 確かめたこと：この 103 字で、四字熟語 35 語・音読みの同じ字の組 31 組（60字）。Notion の D-008・D-013 の数と一致する

### R-002 辞書は jamdict-data の sqlite を直接読む

- 決めたこと：build_data.py は `jamdict_data` パッケージ内の jamdict.db を sqlite3 で読む。`--db` で直接パスも渡せる
- 理由：jamdict 本体（puchikarui 依存）は Python 3.13 でビルドに失敗した。jamdict-data も system pip（古い setuptools）では入らず、venv で pip・setuptools を上げると入った
- 却下：jamdict の API を使う（入らない環境がある）

### R-003 words.json の選び方

- 決めたこと：JMdict の漢字表記のうち、1〜4字で全部が kanji.json の字のもの。古い字・不規則な表記の印（out-dated / irregular kanji）は外す。同じ表記が複数の項目にあるときは「よく使う」のほうを採る
  - かな：その表記に使える最初のかな（re_restr を見る。nokanji は外す）
  - よく使う：news1・ichi1・spec1・spec2・gai1 のどれか（JMdict の慣例）
  - 四字熟語：同じ表記のどれかの項目の sense に yojijukugo がある
  - 英語：最初の2つの意味（それぞれ最初の2語を ; でつなぐ）
- 結果：1,985 語（1字 97・2字 1,391・3字 377・4字 120）。よく使う 652、四字熟語 35

### R-004 同じ読みの組は音と訓を分けて作り、ふるいはまだかけない

- 決めたこと：音読み同士・訓読み同士で組にする（コウ と こう は別の組）。訓読みは送りがな（. の後）を落として比べる（やす.む・やす.い → やす）。2字以上の組だけ残す
- 結果：61 組（音 31・訓 30）
- 懸念：訓読みの1音（い・お・か・き など）の組が多く、ほとんどの札に「音」の印が付く。D-014 の「ふるいが要る見込み」が当たった。ふるい方は未確定（SESSION_STATE）
- 却下：音と訓を混ぜる（同じ音のかなでも別の読みとして扱うほうが、学習者に分かりやすい見込み）

### R-005 部品表は [左（上）, 右（下）] の順。くっつけるはその順に並べたときだけ

- 決めたこと：parts.json は「字：[左, 右]」。台に左→右の順で並べたときだけくっつく
- 理由：上＝卜一・下＝一卜 のように、順を見ないと区別できない
- 却下：順を問わない（上と下が同じ2枚から作れてしまう）

### R-006 偏の形（亻など）は「台に2枚並べて、くっつけられるとき」の左の札で見せる

- 決めたこと：台が2枚で、左の札が radical_forms.json にあり、くっつけられるときに、その札を亻・飠・訁・礻 で見せる。下に小さくもとの字を出す。札そのものは人・食・言・示 のまま
- 理由：人口・言語 のように、くっつけずに語として並べるときは人・言のまま見せたい
- 表の中身：KJ-001 の指示どおり 人・食・言・示。Notion D-007 の例（氵・扌・忄）は、N5 の部品表に使う字がないので入れていない

### R-007 最初の手と袋

- 決めたこと：袋は一人ずつ別。N5 の字を各2枚ずつ（206枚）混ぜ、上から6枚。これで「同じ字は2枚まで」になる
- 却下：二人で同じ袋（相手の引きで自分の袋が変わる。モックでは不要）

### R-008 カゴが空になったら袋から6枚

- 決めたこと：投げたあとカゴが空なら、袋から6枚入る
- 理由：届く札だけだと、二人とも手が尽きて止まりうる
- 却下：時間ごとに袋から1枚落ちる（ひらがな版 D-003「急かすのは時計ではなく相手」の先例とぶつかる）／「引く」操作を足す（操作が6つになり、芯の「操作の形」に触る）

### R-009 CPU は1段階。2〜4秒ごとに1手

- 決めたこと：CPU は 2〜4 秒おきに次の順で1手だけ打つ（数値は rules.json）
  1. 50% で（カゴが残り4マスを切ったら必ず）、手持ちで作れる「よく使う」2〜4字の語を探し、いちばん長いものを投げる
  2. くっつけて N5 の字になる組があればくっつける（なければ中継ぎの部品でも）
  3. 40% で（埋まってきたら必ず）N5 の字を1字で投げる
  4. 巡り・反転をときどき使う（同音は使わない）
- 理由：KJ-001「手持ちで作れる語をときどき投げる。強さは1段階でよい」

### R-010 遊びの画面は「台」に並べてから操作する

- 決めたこと：カゴの札をタップすると台に並ぶ（タップした順が左から）。操作は台の札に対して行う。1枚なら割る・反転・巡り・同音、2枚ならくっつける、語になっていれば投げる。操作でできた札は台に残る（休 を作ってそのまま 日 を足して 休日、と続けられる）
- 理由：くっつける順（R-005）と投げる語の順を、同じ「並べる」でそろえられる

### R-011 1字で投げても、その字は投げ済みになる

- 決めたこと：「休」を1字で投げたら、二人とも「休」を1字では二度と投げられない。「休日」は投げられる（D-005 の言葉ごと）

### R-012 特別な語と「つながる相手」

- 決めたこと：special.json に `{"w": 語, "next": [つながる相手]}`。投げた人の直前の一投が特別な語で、今の語が next にあれば、2つをつなげて大きく出す。N5 版の next は空
- 演出：画面に1字ずつ大きく出すだけ（D-015 の作り込みは後回し）

### R-013 届いた札はカゴの後ろに足し、しばらく朱の枠で示す

- 決めたこと：届いた札だけ 1.5 秒、朱の枠を付ける。自分の操作でできた札には付けない
- 色：強調色は朱1色。投げるボタン・印・届いた札・負け・残りわずかのカゴ数に使う

### R-014 CPU の札には印を出さない。スマホでは自分のカゴを5列にする

- 理由：CPU の札は小さく、印が字に重なって読めない。スマホの幅だと10列では印も字もつぶれる

### R-015 1枚の HTML に JS・CSS を入れ、data/ を同じオリジンから読む

- 決めたこと：index.html 1枚＋data/*.json。外のサーバーとは通信しない。file:// では fetch できないので、Pages かローカルのサーバーで開く
- 数値（カゴ・待ち時間・CPU）は data/rules.json に出す

### R-016 十＋口 は 古 と 田 のどちらにもなる。くっつけるときに選ぶ

- 調べたこと：作者が「口・十 を並べても古にならない」と言った件。理由は2つあった
  1. くっつけるは左→右の順だけ（R-005）。古＝[十, 口] なので 口・十 の順ではくっつかない
  2. 十・口 の順でも、parts.json では 古＝十口 と 田＝十口（D-011・D-016）が同じ左右で、表を引くときに後の 田 が 古 を上書きしていた。KJ-001 のままでは 古 はくっつけて作れなかった
- 決めたこと：同じ左右から2つ以上の字ができるときは、くっつけるを押したあとに台の下で字を選ぶ。CPU はどちらかを無作為に選ぶ。データ（parts.json）は変えない
- 却下：田 か 古 の部品を変える（D-011 の赤入れに触る。作者の判断が要る）／先に書いた方を優先（古 か 田 のどちらかが作れなくなる）
- テスト：同じ左右から2字できるのは 十口 だけ、を data.test.js で見張る。増えたらテストが落ちる

### R-017 台の高さを固定し、選ぶ札は台の下に重ねて出す

- 決めたこと：台の並び 72px・説明 2行（46px、あふれたら切る）で固定。同音とくっつけるの候補は、カゴを押し下げず台の下に重ねて出す。待ち時間の数字は幅を取っておく（数字が出てもボタンが折り返さない）。台に出した札のマスは点線で残し、ほかの札が詰まらない（点線のマスをタップしても台から戻る）
- 理由：作者「選んだ語が上に行くんだがそのたびにズレるの勘弁」。KJ-001 では、英語の説明が2行になる語で +5〜27px、同音の候補で +126px カゴが下がった（375px 幅で計測）
- 却下：台を画面の下に固定（モックで画面の組み替えは大きすぎる。見た目の作り込みはやらない）

### R-018 ログの「ためした」は、並べたのにやめた並びを残す

- 決めたこと：台に2枚以上並べて、投げられず・くっつけられない並びのまま、台の札を戻した（札のタップか「戻す」）ときに「ためした」として残す。理由（辞書にない／投げ済み／並べる順が逆）をメモに書く。同じ並びが続けて出ても1回だけ
- 理由：ボタンは押せないときは押せないので、「押してはじかれた」記録は取れない。並べる途中（天上天 → 天上天下）を全部残すと多すぎる
- 却下：台が変わるたびに全部残す（途中の並びばかりになる）

### R-019 ログは「# の頭」と「タブ区切りの表」。一手ごとに1行

- 決めたこと：頭に はじめた時刻・設定3つ・決まり（カゴ・最初の手・待ち時間・CPU・落ちてくる間隔）・データの版・字と語の数。表は 秒／どちら／手／使った札／できた札／あなたのカゴ／CPUのカゴ／メモ。手は はじめ・割る・くっつける・反転・巡り・同音・投げる・ためした・落ちてくる・補充・終わり。カゴの数はその手のあと
- 取り出し：上の「ログ」で見る（開いている間は手のたびに更新）・コピー。終わったら「ログをコピー」が出る
- 理由：表計算にそのまま貼れる。チャットに貼っても読める

### R-020 試し用の切り替えは上の「設定」。次の「はじめる」から効き、端末に覚える

- 決めたこと：「はじめる」の横に「設定」ボタン。開くと3つの切り替え（できた語の行き先・時間で落ちてくる・CPU の間隔）。初期値は KJ-001 の形。localStorage に覚える。数値（8秒・2〜4秒・8〜12秒）は rules.json（drop_every_sec・cpu.pace）
- 決まりの細部（仮）
  - 消える／おじゃま札 でも、投げた語は投げ済みになる（D-005）。カゴが空になったら袋から6枚は同じ
  - 時間で落ちてくる：二人に同時に1枚。落ちてあふれたら負け。二人同時にあふれたら引き分け
  - 消える＋落ちてこない、の組では相手のカゴは増えないので、勝ち負けがつかない（設定は止めない）
- R-008 との関係：R-008 で却下した「時間ごとに袋から1枚落ちる」は、作者の「時間で漢字が追加される方がいいかも」を受けて切り替えとして入れた。初期値は なし のまま。決まりにするかは作者が試して決める
- 却下：URL のパラメータで切り替え（スマホで変えにくい）

### R-021 おじゃま札は「■」。台に出せず、ずっと残る

- 決めたこと：■ は割れない・くっつけられない・投げられない。タップしても台に出ない（灰色の札）。消す方法はまだない。印は付かない
- 理由：依頼の仮置き（割れず、くっつけられない札が字数ぶん）。消し方を決めるのは試したあと

### R-022 遊びの決まりを js/core.js に分け、テストは Node の node:test（依存なし）

- 決めたこと：DOM に触らない決まり（表引き・割る・くっつける・投げる・待ち時間・CPU・ログ）を js/core.js に出し、index.html と tests/ の両方から使う。時計と乱数は差し替えられる（テストで待ち時間と CPU を決まった形で回す）

- 却下：Jest・Vitest（package を入れる手間。モックは依存なしで置きたい）／index.html の中のまま（テストから呼べない）

### R-023 ログに「動けない」を残す（KJ-002 追記）

- 決めたこと：手札をそのまま並べて投げられる語（投げ済みでない N5 の1字か辞書の語）が1つも無くなった時点で、その人の「動けない」を1行残す。使った札の欄＝その時の手札、メモ＝「投げられる語なし。使える手：割る・反転（待ち 4秒）」のように、投げる以外で使える手と残りの待ち時間。続くあいだは1回だけ。投げられる語ができたら「動ける」（メモに語の例）を残す
- 調べる時：はじめと、札が変わる手（割る・くっつける・反転・巡り・同音・投げる・落ちてくる・補充）のたびに、二人とも
- 理由：作者「相手の手札が『古』だけで、ぼくが『古』を投げたら相手は何もできなくなった」。封じが起きた場面を拾う
- 細部（仮）：カゴが空のときは残さない（すぐ袋から補充されるため）。■ は語にならないので数えない。台に並べている途中かどうかは見ない（手札の中身だけで決める）
- 却下：割る・くっつけるなどをしても投げられる語に届かない、まで調べる（手が多いと重い。まずは「今投げられる語があるか」で場面を拾い、使える手をメモに添える）

## KJ-003「役づくりの競争」への作り直し（2026-11-21、受け箱 P-003。係＝Claude）

### R-025 場・手札・山（カードの仮置き）

- 決めたこと：場は表向き6枚。最初の手札8枚、手札の上限12枚。山は N5 の字を2枚ずつ（206枚）混ぜたもの1つを二人で使い、尽きたら同じものを足す
- 係の細部：取って空いた場は、同じ位置に山の一番上を出す（場の並びが動かない）。手札が12枚のときは 取る・割る ができない（取れる枚数は残る）
- KJ-001 の「カゴ 20 マス・あふれたら負け・空なら袋から6枚」（D-013・R-番号）は、この形では使わない

### R-026 点数（カードの仮置き）

- 決めたこと：1字1・2字3・3字6・4字12。四字熟語の印つき（words.json の yoji）は倍、特別な語（天上天下）はさらに倍（天上天下＝48点）
- 「火力」（D-002）は点数として生きる。部品にバラして届く（D-003・D-004）は使わない。js/core.js の delivered() とそのテストは残した（消すかは作者が決める）

### R-027 放つ・取る・引き直し・勝ち・CPU（カードの仮置き）

- 放つ：words.json の語（1〜4字）か N5 の1字。放った言葉は消える（相手には届かない）。一度放った言葉は二人とも二度と使えない（言葉ごと。D-005）
- 取る：放った字数と同じ枚数を、場から選んで取れる。手番はなく早い者勝ち（相手が先に取った札は取れない）
- 引き直し：5点払って手札を全部入れ替える（8枚）。5点ない人は30秒待てば0点で入れ替わる
- 勝ち：先に50点。または5分で点の多い方
- CPU：8〜12秒に1回動く（速さで強くしない）
